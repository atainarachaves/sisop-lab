Introdução aos sistemas operacionais

Um sistema operacional é um programa que faz a intermediação entre o usuário e o hardware. Seus objetivos: executar programas do usuário, tornar o computador conveniente de usar e usar o hardware de forma eficiente. Não existe definição universal; a mais prática é: o kernel é o único programa que roda o tempo todo; o resto é programa de sistema (vem com o SO) ou aplicação. SOs de uso geral e móveis também trazem middleware (bancos de dados, multimídia, gráficos).

1.1 Evolução histórica

Lote (batch)

Um usuário sozinho não mantém CPU e E/S sempre ocupadas. Jobs são agrupados e executados em sequência.

Multiprogramação

Vários jobs na memória; quando um espera E/S, o SO troca para outro. A CPU sempre tem algo a executar. Aqui surge o escalonamento de jobs.

Tempo compartilhado (multitarefa)

A CPU troca tão rápido que o usuário interage com cada programa. Resposta < 1 s. Traz escalonamento de CPU, swapping e memória virtual.

Organização do computador e interrupções

CPUs e controladores de dispositivos ligam-se por um barramento à memória compartilhada e executam concorrentemente. Cada controlador tem um buffer local e um device driver no SO. Quando termina, o controlador avisa a CPU por uma interrupção. O SO é dirigido por interrupções.

Ciclo de E/S por interrupção · passo 1 de 7

  • Vetor de interrupções: tabela com o endereço de cada rotina de tratamento. O hardware salva o endereço da instrução interrompida; o SO salva registradores e PC.
  • Trap/exceção: interrupção gerada por software, por erro (divisão por zero) ou pedido do usuário (chamada de sistema).
  • DMA: para E/S rápida, o controlador transfere blocos direto à memória; gera uma interrupção por bloco, e não uma por byte.

Proteção: modo dual e timer

Modo usuário × kernel

Um bit de modo no hardware distingue código de usuário de código do kernel. Instruções privilegiadas só executam em modo kernel. A chamada de sistema muda para kernel; o retorno volta a usuário. Assim o usuário não consegue "se promover" sozinho.

Timer

O SO programa (instrução privilegiada) um contador que decrementa com o relógio; ao zerar, gera interrupção. Evita laço infinito e garante que o SO retome o controle da CPU antes de escalonar um processo.

1.3 Serviços do sistema operacional

Serviços úteis ao usuário e ao programador:

  • Interface com o usuário: linha de comando (shell), gráfica (GUI), toque, batch.
  • Execução de programas: carregar na memória, rodar e terminar (normal ou com erro).
  • Operações de E/S e manipulação do sistema de arquivos.
  • Comunicação entre processos: memória compartilhada ou troca de mensagens.
  • Detecção de erros em CPU, memória, dispositivos e programas.

Há ainda serviços para o funcionamento eficiente do próprio sistema: alocação de recursos, contabilidade e proteção/segurança. Proteção controla o acesso a recursos definidos pelo SO; segurança defende o sistema de ataques internos e externos.

O shell por dentro

O interpretador de comandos busca um comando e o executa. Se o comando é um programa externo, o shell só usa o nome para achar o arquivo: não precisa ser modificado para ganhar comandos novos. Fluxo: o shell chama fork() para criar o processo e exec() para carregar o programa nele; depois wait() ou segue aceitando comandos.

1.4 Chamadas de sistema

É a interface de programação para os serviços do SO. Os programas normalmente usam uma API (Win32, POSIX, Java), e não a chamada diretamente; a biblioteca de execução traduz a chamada da API na chamada de sistema correspondente. Cada chamada tem um número, e o kernel mantém uma tabela indexada por ele.


  
Não confunda: printf() é função da biblioteca C (formata e chama write()); write() é a chamada de sistema que muda para modo kernel.

  
Passagem de parâmetros

  
  • Em registradores (simples, mas podem faltar registradores).
  • Em um bloco/tabela na memória, passando só o endereço em um registrador (Linux e Solaris).
  • Na pilha, empilhados pelo programa e desempilhados pelo SO. Bloco e pilha não limitam o número de parâmetros.

  
Tipos de chamadas

  

    
Controle de processos
criar/terminar, load/execute, esperar evento, alocar memória, locks

    
Arquivos
create, delete, open, close, read, write, reposition, atributos

    
Dispositivos
request/release, read, write, atributos, attach/detach

    
Informação
data e hora, dados do sistema, atributos de processo/arquivo

    
Comunicação
criar conexão, send/receive, memória compartilhada

    
Proteção
permissões, permitir e negar acesso

  

  
Ligadores e carregadores

  
O código-fonte vira objeto relocável; o linker junta objetos e bibliotecas em um executável; o loader o traz à memória e faz a relocação (endereços finais). Formatos: ELF (Unix/Linux), PE (Windows), Mach-O (macOS). Bibliotecas dinâmicas (DLL, .so) são carregadas sob demanda e compartilhadas.

  
Por que um app não roda em outro SO?
Cada SO tem suas chamadas de sistema e formato de arquivo; o equivalente de API em nível binário é a ABI. Portabilidade vem de linguagem interpretada (Python), de VM (Java) ou de recompilar o mesmo código C em cada SO.

Ambientes de computação e arquiteturas

  
  • Multiprocessadores: mais vazão, economia de escala, confiabilidade (degradação graciosa). SMP: todos os processadores fazem todas as tarefas; assimétrico: cada um tem tarefa específica. Também NUMA e multicore.
  • Virtualização: o VMM permite rodar SOs convidados sobre um hospedeiro.
  • Tempo real: restrições de tempo fixas; a operação só está correta se elas forem cumpridas.
  • Outros: cliente-servidor, P2P, nuvem, móvel, embarcado.

Processos

  
Programa é uma entidade passiva (um arquivo executável em disco). Processo é um programa em execução: entidade ativa, com contador de programa, registradores, pilha, heap, seção de dados e texto.


  
Estados de um processo

  
Clique nas transições e veja o processo andar pelo diagrama. Só aparecem as transições válidas a partir do estado atual.

  

    

    

    

  

  
PCB
Cada processo é representado no SO por um Process Control Block (no Linux, task_struct): estado, PC, registradores, informações de escalonamento, memória, E/S. É o que a troca de contexto salva e restaura. A troca é puro overhead: durante ela, nenhum processo do usuário avança.


  
Criação e término

  

  
    
    
  • fork() devolve 0 no filho e o PID do filho no pai; pai e filho executam o mesmo código a partir dali.
    • 
    
  • exec() substitui a imagem do processo por outro programa. wait() bloqueia o pai até um filho terminar.
    • 
    
  • Zumbi: filho terminou, mas o pai ainda não chamou wait(); a entrada na tabela de processos permanece. Órfão: o pai terminou antes do filho; o init adota.
    • 
  

  
Pegadinha clássica
Um laço for (i=0;i<n;i++) fork(); cria 2n − 1 filhos (2n processos no total), porque os filhos também continuam o laço. Para uma cadeia, o filho precisa sair do laço (break); para uma árvore rasa, é o pai que cria e o filho sai.

Escalonamento de CPU

  
O escalonador escolhe, entre os processos prontos, qual vai usar a CPU. O despachador (dispatcher) entrega a CPU ao escolhido: troca de contexto, volta ao modo usuário e salto ao ponto certo. O tempo que ele gasta é a latência de despacho.

  
Quando o escalonador é chamado

  
  1. Executando → esperando (pedido de E/S)
  2. Executando → pronto (interrupção)
  3. Esperando → pronto (E/S terminou)
  4. Terminação

  
Se só 1 e 4 ocorrem, o escalonamento é não preemptivo; se 2 e 3 também, é preemptivo (e exige cuidado com dados compartilhados).


  
Critérios

  

    
MétricaDefiniçãoQuer-se

Vazão (throughput)processos concluídos por unidade de tempomaximizar

    
Turnaroundtérmino − chegadaminimizar

    
Esperatempo total na fila de prontos = turnaround − burstminimizar

    
Respostaprimeira execução − chegadaminimizar

  


  
Algoritmos

  

    
FCFS
Fila simples, não preemptivo. Sofre do efeito comboio: processos curtos esperam atrás de um longo.

    
SJF / SRTF
Menor próximo burst primeiro. É ótimo no tempo médio de espera. SRTF é a versão preemptiva. O difícil é prever o burst; causa starvation de jobs longos.

    
Round Robin
Cada processo recebe um quantum q. Com n processos, ninguém espera mais que (n−1)·q. Se q é enorme vira FCFS; se é minúsculo, a troca de contexto domina.

    
Prioridades
Menor número = maior prioridade (convenção dos slides). Risco de starvation; remédio: aging. Pode ser combinada com RR entre prioridades iguais.

Threads

  
Uma thread é a unidade básica de uso da CPU. Um processo tradicional tem uma só; um processo multithread tem vários fluxos de execução dentro do mesmo espaço de endereçamento.

  

    
Compartilhado
  • Código (texto)
  • Dados globais e heap
  • Arquivos abertos

    
Privado de cada thread
  • ID da thread
  • Contador de programa e registradores
  • Pilha (stack)

  

  
Benefícios (Silberschatz): responsividade, compartilhamento de recursos, economia (criar e trocar thread é mais barato que processo) e escalabilidade em multiprocessadores.

  
Não confunda
Concorrência = várias tarefas progredindo, mesmo que intercaladas em um núcleo só. Paralelismo = várias tarefas executando literalmente ao mesmo tempo, o que exige mais de um núcleo.


  
Threads de usuário × de kernel

  

    
ModeloMapeamentoPonto fortePonto fraco

    
Muitos-para-umN usuário → 1 kernelGerência barataUma chamada bloqueante trava tudo; sem paralelismo

    
Um-para-um1 usuário → 1 kernelConcorrência real, não trava tudoCusto de criar thread de kernel (Linux, Windows)

    
Muitos-para-muitosN usuário → M kernel (M ≤ N)FlexívelComplexo de implementar

    
Dois níveisM:N + opção de ligar uma thread a uma de kernelMistura dos doisComplexidade

O problema da seção crítica

  
Uma solução correta precisa garantir três coisas:

  
  • Exclusão mútua: só um processo na seção crítica por vez.
  • Progresso: se ninguém está dentro, a escolha de quem entra cabe apenas a quem quer entrar, e não pode ser adiada indefinidamente.
  • Espera limitada: há um limite de quantas vezes outros entram antes de quem já pediu.

Petersonflag[2] + turn, só softwarePode falhar em arquiteturas modernas com reordenação de instruções

Semáforos

  

  
    
    
  • Contador: valor irrestrito, controla recursos com várias instâncias. Binário (0 ou 1): comporta-se como mutex.
    • 
    
  • Na implementação com bloqueio, wait coloca o processo numa fila (block) em vez de girar, e signal o acorda (wakeup).
    • 
  


  
Produtor–consumidor (buffer limitado)

  
Semáforos: mutex = 1 (acesso ao buffer), empty = N (posições livres), full = 0 (posições ocupadas).

  

  
Deadlock
Se o produtor fizer wait(mutex) antes de wait(empty) e o buffer estiver cheio, ele segura o mutex dormindo e o consumidor nunca consegue entrar para liberar espaço. A ordem dos wait importa; a dos signal não.

Cada filósofo pega o garfo da esquerda e depois o da direita. Avance um filósofo de cada vez e tente chegar ao deadlock manualmente. Depois compare, em sorteios aleatórios, a versão ingênua com a solução por estados (test()).

  

    

    

    

    

    

  

  
Deadlock × starvation
Deadlock: todos esperam um evento que só outro processo bloqueado pode causar; ninguém avança. Starvation: o sistema avança, mas um processo específico espera indefinidamente (ex.: escritores na solução com prioridade dos leitores).

  
Problemas de vivacidade

  
  • Deadlock: dois processos esperam, cada um, um evento que só o outro pode causar (ex.: P0 faz wait(S), wait(Q); P1 faz wait(Q), wait(S)).
  • Starvation: um processo espera indefinidamente, embora o sistema como um todo avance.
  • Inversão de prioridade: tarefa de alta prioridade espera por lock de baixa; resolve-se com herança de prioridade.

Comunicação entre processos

  
Processos independentes não se afetam; processos cooperantes precisam trocar informação para compartilhar dados, dividir uma tarefa ou por modularidade.

  
Modelos de IPC

  

    
Memória compartilhada
Uma região é mapeada nos dois processos. Rápida (só o setup passa pelo kernel), mas a sincronização é problema seu.

    
Troca de mensagens
send/receive mediados pelo kernel. Mais simples de usar e boa para distribuído, porém com custo de chamada de sistema por mensagem.

  

  
Pipes

  
    
    
  • Ordinário (pipe(fd)): unidirecional, só entre processos aparentados (pai/filho). fd[0] lê, fd[1] escreve.
    • 
    
  • Nomeado (FIFO): tem nome no sistema de arquivos, bidirecional em geral half-duplex, sem exigir parentesco.
    • 
  

  


Ligação com sincronização
Na memória compartilhada, quem garante a exclusão mútua é o programador. Revise Sincronização.

4.1 Conceitos básicos

  
Um conjunto de processos está em deadlock quando cada um espera um recurso que só outro processo do conjunto pode liberar. Um processo usa um recurso em três passos: requisitar, usar e liberar.

  
As quatro condições necessárias (têm de valer ao mesmo tempo)

  

    
1. Exclusão mútua
Pelo menos um recurso não é compartilhável: só um processo o usa por vez.

    
2. Posse e espera
Um processo segura recursos e espera por outros.

    
3. Não preempção
Recurso só é liberado voluntariamente por quem o detém.

    
4. Espera circular
P0 espera P1, P1 espera P2, ..., Pn espera P0.

  

  
Grafo de alocação de recursos: vértices são processos e tipos de recurso; aresta Pi → Rj é uma requisição; Rj → Pi é uma alocação. Sem ciclo, não há deadlock. Com ciclo: se cada tipo tem uma instância, há deadlock; com várias instâncias, o ciclo é necessário, mas não suficiente.


  
4.2 Prevenção

  
Garantir que pelo menos uma das quatro condições nunca valha:

  

    
Condição negadaComoCusto

    
Exclusão mútuaRecursos compartilháveis (arquivo só de leitura)Nem todo recurso permite (impressora, mutex)

    
Posse e esperaPedir tudo de uma vez, ou só pedir quando não segura nadaBaixa utilização; starvation

    
Não preempçãoSe o pedido não é atendido, o processo libera o que tem; ou o SO retira recursosSó serve para recursos cujo estado se salva (CPU, memória)

    
Espera circularOrdem total dos recursos: requisitar sempre em ordem crescenteÉ a mais usada na prática (ordem de locks)

  

  
Evasão (avoidance): estado seguro e algoritmo do banqueiro

  
Em vez de negar uma condição, o SO exige que cada processo declare o máximo que usará e só concede um pedido se o estado resultante for seguro. Estado seguro: existe uma sequência segura de processos em que cada um consegue terminar com o que está disponível mais o que os anteriores liberam. Estado inseguro não é deadlock, mas pode levar a ele.

  
Matrizes: Disponível, Alocação, Máximo e Necessidade = Máximo − Alocação. O exemplo é o clássico do Silberschatz: recursos A, B, C com 10, 5 e 7 instâncias.

  

    

      
      
      
    

    

    

      
      
      
    

    

  

  
Roteiro do livro: peça (1 0 2) para P1 (concedido); depois (3 3 0) para P4 (recursos insuficientes); depois (0 2 0) para P0 (recusado: estado inseguro).


  
4.3 Detecção e recuperação

  
    
    
  • Detecção: com uma instância por recurso, procura-se ciclo no grafo de espera (wait-for: Pi → Pj se Pi espera recurso de Pj). Com várias instâncias, usa-se um algoritmo parecido com o do banqueiro, mas sem o Máximo: com base no que cada um está pedindo agora. Quem não conseguir terminar ao final está em deadlock.
    • 
    
  • Quando rodar: a cada pedido não atendido (caro) ou periodicamente / quando a utilização da CPU cai.
    • 
    
  • Recuperação: terminar processos (todos os do ciclo ou um de cada vez) ou preemptar recursos (escolher vítima, voltar o processo a um ponto anterior, e evitar que a mesma vítima sofra starvation).
    • 
  

  
Na prática
Sistemas como Linux e Windows costumam ignorar o problema (algoritmo do avestruz) e deixam a ordem de locks por conta do programador. Detecção e evasão ficam para bancos de dados e sistemas especializados.

Gerência de memória

  
A CPU só acessa diretamente registradores e memória principal. O programa precisa estar na memória para executar, e o SO decide o que fica lá e onde. Funções básicas: maximizar o número de processos na memória, permitir programas maiores que a memória física, compartilhar dados e proteger cada processo e o próprio SO.


  
Fundamentos

  
    
    
  • Proteção com registradores base e limite: a CPU confere cada acesso em modo usuário; carregar esses registradores é instrução privilegiada.
    • 
    
  • Ligação de endereços (binding) pode ocorrer em compilação (código absoluto), carga (código relocável) ou execução (exige hardware: MMU).
    • 
    
  • Endereço lógico (virtual) é o gerado pela CPU; físico é o visto pela memória. A MMU faz o mapeamento em tempo de execução; no esquema simples, soma o registrador de relocação a cada endereço lógico.
    • 
    
  • Carga dinâmica: a rotina só é carregada quando chamada. Ligação dinâmica: um stub localiza a rotina da biblioteca compartilhada na hora da execução.
    • 
  


  
5.1 Políticas básicas: alocação contígua

  
Cada processo ocupa uma única região contígua. A memória se divide em partição do SO e partição(ões) de usuário; base e limite protegem os processos entre si.

  

    
Partições fixas
Tamanhos definidos na inicialização. Alocação absoluta: o programa só carrega em um endereço (uma partição). Relocável: pode ir em qualquer partição que caiba. Sofre fragmentação interna.

    
Partições variáveis
Cada processo recebe uma partição do seu tamanho; sobram buracos (holes). Ao sair, partições livres adjacentes se juntam. Sofre fragmentação externa.

  

  
Onde colocar o processo? (problema da alocação dinâmica)

  

    
EstratégiaRegraEfeito

    
First-fitPrimeiro buraco que couberRápida: não varre tudo

    
Best-fitMenor buraco que couberMenor sobra, mas deixa muitos buracos minúsculos; varre a lista inteira

    
Worst-fitMaior buracoMaior sobra (talvez reaproveitável); também varre tudo

  

  
Interna × externa
Interna: memória dentro da partição alocada que o processo não usa (partição maior que o pedido; a última página na paginação). Externa: há memória livre suficiente no total, porém espalhada em pedaços pequenos demais. Compactação reduz a externa, mas só se a relocação for dinâmica (em tempo de execução).

Paginação

  
A memória física se divide em quadros (frames) de tamanho fixo (potência de 2; hoje 4 KB ou 8 KB; no Linux: getconf PAGESIZE) e a lógica em páginas do mesmo tamanho. O espaço físico do processo deixa de ser contíguo: acaba a fragmentação externa, mas resta fragmentação interna na última página.

  
Tradução de endereço
Endereço lógico de m bits com página de 2n bytes: os m−n bits altos são o número da página (p, índice na tabela de páginas) e os n bits baixos o deslocamento (d). O endereço físico é quadro × tamanho + d.

  
Laboratório: tradução de endereços

  

    

      
      
    

    

    

  

  
Tabela de páginas, TLB e proteção

  
    
    
  • A tabela fica na memória; o PTBR aponta para ela e o PTLR informa seu tamanho. Sem ajuda, cada acesso custa dois acessos à memória (tabela + dado).
    • 
    
  • A TLB (memória associativa, 32 a 1.024 entradas) guarda traduções recentes. ASID identifica o processo dono da entrada; sem ASID, a TLB é esvaziada a cada troca de contexto.
    • 
    
  • Bit válido/inválido: página fora do espaço lógico gera trap. Bits de proteção (leitura, escrita, execução) por quadro.
    • 
    
  • Páginas compartilhadas: uma cópia de código reentrante (que não se modifica) mapeada em vários processos.
    • 
  

  
Estrutura da tabela de páginas

  
32 bits com páginas de 4 KB dão 220 entradas; com 4 bytes cada, 4 MB por processo só de tabela, e contíguos. Soluções:

  

    
Hierárquica
"Paginar a tabela": 32 bits = 10 (p1, tabela externa) + 10 (p2, tabela interna) + 12 (deslocamento). Em 64 bits fica inviável (muitos acessos).

    
Com hash
Número da página virtual passa por hash; cada posição guarda uma lista encadeada (colisões). Comum acima de 32 bits.

    
Invertida
Uma entrada por quadro físico <pid, página>. Menos memória, busca mais lenta (use hash e TLB).

  

  
Swapping

  
Um processo inteiro pode ser levado temporariamente ao backing store (swap out) e trazido de volta (swap in). Permite que o total de memória dos processos exceda a física. O tempo é dominado pela transferência. Em sistemas móveis normalmente não existe (flash limitada): o iOS pede que apps liberem memória e o Android encerra apps.


  
5.2 Memória virtual

  
Memória virtual separa a memória lógica da física: só parte do programa precisa estar na memória, e o espaço lógico pode ser muito maior que o físico. Mais programas cabem ao mesmo tempo (mais utilização de CPU) e há menos E/S para carregar ou trocar. Funciona porque os programas têm localidade de referência.

  
Paginação sob demanda

  
Uma página só vem do disco quando é referenciada (lazy swapper/pager). Cada entrada tem o bit válido/inválido (v = na memória, i = fora). Referência a página i gera page fault.

  
    
    
  1. A referência gera trap para o SO.
    2. 
    
  2. O SO consulta outra tabela: referência inválida → aborta; só não está na memória → continua.
    3. 
    
  3. Acha um quadro livre (lista de quadros livres, zero-fill-on-demand).
    4. 
    
  4. Agenda leitura do disco para o quadro; a CPU atende outro processo enquanto espera.
    5. 
    
  5. Atualiza as tabelas e põe bit = v.
    6. 
    
  6. Reinicia a instrução que causou a falta.
    7. 
  

  
No pure demand paging o processo começa sem nenhuma página na memória. Uma taxa alta de page faults deixa o sistema lento, pois cada falta custa uma E/S de disco.

  
Copy-on-Write

  
Após fork(), pai e filho compartilham as páginas; só quando um deles escreve, aquela página é copiada. Como muitos filhos chamam exec() logo, evita-se copiar o espaço do pai à toa (usado em Linux, Windows e macOS; vfork() é a variante em que o pai fica suspenso).

  
Substituição de páginas

  
Se não há quadro livre, o SO escolhe uma vítima. O bit de modificação (dirty) evita gravar em disco páginas não alteradas; com vítima suja ocorrem duas transferências por falta. A qualidade se mede pelo número de page faults numa string de referências (só números de páginas; repetir a mesma página seguida não gera falta).

  

    
AlgoritmoRegraObservação

    
FIFORemove a página mais antiga (fila)Simples, mas pode remover página muito usada; sofre da anomalia de Belady: mais quadros podem gerar mais faltas

    
Ótimo (OPT)Remove a página que ficará mais tempo sem usoImpossível na prática (exige conhecer o futuro); serve de referência

    
LRURemove a menos recentemente usadaBom e muito usado; implementação por contador (busca o menor) ou por pilha (move a referenciada para o topo; sem busca)

Segmentação

  
(Os slides de segmentação não estão no projeto; resumo conforme o Silberschatz, cap. 9.) Na paginação o espaço é dividido em blocos de tamanho fixo, invisíveis ao programador. Na segmentação o espaço é dividido em unidades lógicas de tamanho variável (código, pilha, dados, bibliotecas). O endereço é <segmento, deslocamento>; a tabela de segmentos guarda base e limite de cada um, e deslocamento ≥ limite gera trap. Paginação evita fragmentação externa e tem interna; a segmentação tem externa, mas reflete a visão do programador e facilita proteção e compartilhamento.


  
5.3 Sistemas de memória não-volátil e armazenamento em massa

  

    
HDD
Pratos magnéticos girando; tempo de posicionamento = seek (mover o braço ao cilindro) + latência rotacional. O SO quer minimizar o seek.

    
NVM / SSD
Sem partes móveis, sem seek: muito mais rápido e mais IOPS. Mas escreve em páginas, não sobrescreve no lugar (apaga em blocos maiores) e tem ~100.000 apagamentos de vida útil (DWPD). Interface NVMe direto no PCI.

Gerência de arquivos

  
O SO dá uma visão lógica e uniforme do armazenamento: abstrai as propriedades físicas e oferece o arquivo, um espaço lógico contíguo de dados (numéricos, caracteres, binários) ou programa. O conteúdo é definido por quem o cria.


  
6.1 Arquivos

  
Atributos

  
Nome (única informação legível por humanos), identificador (número único no sistema de arquivos), tipo, localização, tamanho, proteção, data/hora e usuário. Ficam na estrutura de diretórios, no disco.

  
Operações

  
    
    
  • Create (achar espaço + criar entrada no diretório), write e read (com ponteiro de posição), seek (reposicionar), delete, truncate (esvazia mantendo atributos).
    • 
    
  • open(F) busca a entrada no diretório e a traz à memória; close(F) a grava de volta. Evita pesquisar o diretório a cada operação.
    • 
  

  
Tabelas de arquivos abertos
Dois níveis: a tabela por processo (guarda, por exemplo, o ponteiro atual de cada arquivo) aponta para a tabela global do sistema (localização no disco, datas, tamanho e o contador de aberturas). O descritor retornado por open() é um índice na tabela do processo.

  
Travas de arquivo

  
Parecidas com leitores–escritores: trava compartilhada (vários leitores) e exclusiva (escritor). Obrigatória (Windows): o acesso é negado conforme as travas. Consultiva (Unix): os processos consultam e decidem.

  
Tipos e estrutura

  
O tipo pode vir na extensão do nome. O Unix usa um número mágico no início de arquivos binários (PDF: 25 50 44 46; ZIP: 50 4b 03 04; GIF: 47 49 46 38). Unix e Windows tratam o arquivo como sequência de bytes: máxima flexibilidade, mas cada programa interpreta seu formato. Todo SO precisa conhecer ao menos o formato executável.

  
Métodos de acesso

  

    
Sequencial
read_next, write_next, reset. O mais comum (editores, compiladores).

    
Direto (relativo)
read(n), write(n) com n = nº de bloco relativo ao início do arquivo (0, 1, 2...). Bancos de dados.

    
Indexado
Um índice (como o de um livro) aponta para blocos; arquivos grandes podem ter índice do índice.

  


  
6.2 Diretórios

  
O diretório é uma tabela de símbolos: traduz nomes em blocos de controle de arquivo (FCB/i-node). Operações: procurar, criar, apagar, listar e renomear.

6.5 Segurança e arquivos mapeados em memória

  
Proteção é o controle de acesso a recursos definidos pelo SO; segurança é a defesa contra ataques. Os slides de arquivos do projeto cobrem a proteção; para segurança veja o cap. 16 do Silberschatz.

Gerência de entrada e saída

  
A E/S é um dos grandes componentes do projeto de um SO: dispositivos muito variados, vários métodos de controle, gerência de desempenho e novos dispositivos o tempo todo. Os device drivers encapsulam os detalhes e apresentam uma interface uniforme ao subsistema de E/S.


  
7.1 Dispositivos de E/S: hardware

  
    
    
  • Porta: ponto de conexão. Barramento: acesso direto compartilhado (PCI/PCIe, SAS). Controlador (host adapter): eletrônica que opera porta, barramento ou dispositivo; os complexos (Fibre Channel, HBA) têm processador, microcódigo e memória própria.
    • 
    
  • Registradores do dispositivo: data-in, data-out, status e control. O driver escreve comandos e lê resultados.
    • 
    
  • Como endereçar: instruções de E/S dedicadas (endereço de porta) ou E/S mapeada em memória (registradores no espaço de endereços, acessados com instruções normais).
    • 
  


  
7.2 Controladores: três formas de transferir dados

  

    
TécnicaComo funcionaQuando

    
Polling (E/S programada)A CPU lê repetidamente o bit busy (espera ocupada), escreve o comando, ativa command-ready e o controlador executa e limpa os bitsRazoável se o dispositivo é rápido; ineficiente se é lento

    
InterrupçõesO dispositivo aciona a linha de pedido de interrupção; a CPU confere após cada instrução e desvia pelo vetor. Interrupções mascaráveis ou não, com prioridade e encadeamentoEventos sem custo de espera; também usadas em exceções, page faults e system calls (trap)

    
DMAO SO escreve na memória um bloco de comando (origem, destino, modo, nº de bytes); o controlador de DMA move os dados sem a CPU (cycle stealing) e interrompe ao finalGrandes volumes de dados

  

  
Mesmo sistemas de um usuário tratam centenas de interrupções por segundo e servidores, centenas de milhares; por isso o tratamento precisa ser rápido.


  
7.3 Drivers e interface de aplicação

  
As chamadas de E/S encapsulam o dispositivo em classes genéricas; o driver esconde as diferenças entre controladores. Os dispositivos variam em:

  

    
Fluxo de caracteres × bloco
byte a byte (teclado) × bloco como unidade (disco)

    
Sequencial × acesso aleatório
ordem fixa × qualquer posição (seek)

    
Síncrono × assíncrono
tempo de resposta previsível × imprevisível

    
Compartilhável × dedicado
vários processos ao mesmo tempo × um só

    
Velocidade
de bytes/s a GB/s

    
Leitura/escrita
ambos, só leitura ou só escrita

  

  
Duas formas de uma chamada de E/S: bloqueante (o controle só volta ao programa quando a E/S termina) ou não bloqueante/assíncrona (volta sem esperar; o SO usa uma device-status table com tipo, endereço e estado de cada dispositivo).


  
Subsistema de E/S do kernel

  

    
ServiçoFunção

    
EscalonamentoOrdena as requisições numa fila por dispositivo (imparcialidade, QoS)

    
BufferingMemória temporária na transferência: compensa diferença de velocidade e de tamanho de transferência e mantém a "semântica de cópia". Double buffering desacopla produtor e consumidor

    
CachingCópia em memória mais rápida; sempre é só uma cópia (o buffer pode ser o único exemplar dos dados)

Buffer: guarda dados em trânsito entre duas velocidades. Cache: guarda cópia de dados para acessar mais rápido. Spool: guarda a saída inteira de jobs para um dispositivo que não intercala requisições.


  
Ciclo de vida de uma requisição de E/S

  
(Resumo conforme o Silberschatz; o slide é uma figura.)

  
    
    
  1. O processo faz uma system call bloqueante de leitura.
    2. 
    
  2. O kernel verifica se os dados já estão no buffer/cache; se sim, devolve.
    3. 
    
  3. Senão, bloqueia o processo e enfileira a requisição; o driver programa o controlador.
    4. 
    
  4. O controlador executa a operação e, com DMA, leva os dados à memória.
    5. 
    
  5. O dispositivo interrompe; o tratador identifica o dispositivo e conclui a requisição.
    6. 
    
  6. O kernel desbloqueia o processo (volta à fila de prontos) e copia os dados ou o status.
    7. 
  

  
Desempenho

  
A E/S pesa na CPU (driver e código do kernel), nas trocas de contexto por interrupção, na cópia de dados e no tráfego de rede. Para melhorar: reduzir trocas de contexto e cópias, reduzir interrupções (transferências grandes, controladores inteligentes, polling), usar DMA, usar hardware mais esperto e balancear CPU, memória, barramento e E/S.

  
Ligação com as outras unidades
Interrupções e DMA retomam a Unidade 1; o disco e o escalonamento de disco estão em 5.3; spooling e reserva de dispositivo se ligam a sincronização e deadlock.
